# 构建、配置与运维

## 1. 本地开发

安装依赖：

```bash
npm.cmd install
```

启动 Tauri 开发模式：

```bash
npm.cmd run tauri dev
```

前端单独启动：

```bash
npm.cmd run dev
```

前端构建和类型检查：

```bash
npm.cmd run build
```

Rust 检查：

```bash
cd src-tauri
cargo check
```

## 2. nano 终端客户端

`nano` 与桌面端复用同一个 Rust LLM 实现、模型配置数据库、项目索引和会话存储。项目模式的对话会写入现有 `conversations/messages`，退出后可以恢复；`--temp` 模式仍只保存在当前进程内。

Windows 安装命令：

```powershell
npm.cmd run install:nano
```

该命令会构建 release 版 `nano.exe`，默认安装到当前 `cargo.exe` 所在目录（Rustup 的常见位置是 `%USERPROFILE%\.cargo\bin`）。安装脚本会确认该目录已在当前 `PATH` 中，安装后可直接使用：

```powershell
# 当前目录项目问答；启动时更新代码和文档索引
nano

# 恢复当前项目最近一次会话
nano --continue

# 查看会话并按 ID 恢复（支持唯一 ID 前缀）
nano --sessions
nano --resume 1234abcd

# 指定项目目录
nano --project D:\workspace\demo --continue

# 普通临时对话，不绑定项目
nano --temp

# 单次提问后退出
nano -p "这个项目的启动入口在哪里？"
nano --temp -p "帮我整理一个会议提纲"
```

交互命令：

- `/help`：查看交互命令。
- `/clear`：临时模式清空上下文；项目模式结束当前会话，下一条消息创建新会话。
- `/model`：查看可用模型。
- `/model <名称或 ID>`：切换模型。
- `/exit`：退出。

常用启动参数：

- `-C, --project <目录>`：指定项目根目录。
- `--temp`：普通临时对话。
- `--continue`：恢复当前项目最近更新的未归档会话。
- `--resume <会话ID>`：恢复当前项目指定会话，支持唯一 ID 前缀。
- `--sessions`：按更新时间列出当前项目可恢复会话。
- `-p, --prompt <问题>`：单次提问。
- `-m, --model <模型>`：按配置名称、模型名或 ID 选模型。
- `--no-index`：不在启动时重建项目索引，使用已有索引。
- `--data-dir <目录>`：覆盖桌面端应用数据目录。

CLI 默认读取桌面端 `com.nanoagent.desktop` 应用数据目录中的模型配置，因此首次使用前需要先在桌面端配置至少一个聊天模型。项目模式会更新共享数据库中的代码和文档索引，并与桌面端共用项目会话；临时模式不会绑定、扫描项目或写入对话历史。恢复会话时默认沿用会话保存的模型，也可以通过 `--model` 或交互命令 `/model` 切换。

仅构建、不安装：

```powershell
cargo build --release --bin nano --manifest-path src-tauri\Cargo.toml
```

## 3. Windows 打包

推荐命令：

```bash
npm.cmd run package:win
```

该命令执行 `scripts/build-installer.ps1`，流程包括：

1. 定位 Visual Studio Build Tools 的 `vcvars64.bat`。
2. 注入 MSVC x64 构建环境。
3. 调整 PATH，避免 Git for Windows 的 `link.exe` 抢占 MSVC linker。
4. 执行 Tauri build。
5. 输出 release exe、NSIS 和 MSI 路径。

常见产物位置：

```text
src-tauri/target/release/nano-agent.exe
src-tauri/target/release/bundle/nsis/*.exe
src-tauri/target/release/bundle/msi/*.msi
```

## 4. 应用数据与清理

运行时数据位于 Tauri app data 目录。主要文件：

- `nano-agent.sqlite3`
- `nano-agent-runtime.sqlite3`
- `nano-agent-observability.sqlite3`
- `settings.json`
- `skills/`
- `temp/`

清理建议：

- 排查业务数据问题时优先备份 `nano-agent.sqlite3`。
- 运行时记录异常膨胀时可考虑清理 `nano-agent-runtime.sqlite3`。
- 观测数据可在设置页清空，也可以删除 `nano-agent-observability.sqlite3` 后重启重建。
- `temp/` 是普通会话的临时工作目录，也可能保存普通会话图片附件；清理前确认是否还需要历史图片预览。

## 5. 配置项

### 5.1 模型

聊天模型配置包括：

- provider
- base URL
- model
- API key

Anthropic 使用 Messages API；OpenAI、OpenRouter、Ollama 等走 OpenAI-compatible API。

### 5.2 Embedding

Embedding 配置独立于聊天模型，用于 RAG：

- embedding provider
- embedding base URL
- embedding model
- embedding API key

未填写时会回退到聊天模型配置。默认模型名为 `text-embedding-3-small`。

### 5.3 Tavily

Tavily API key 保存在 `settings.json`，用于可选互联网检索相关能力。

### 5.4 MCP

MCP 配置保存在主业务库。stdio server 可以设置命令、参数、环境变量和工作目录；HTTP 类 server 可以设置 URL 和 headers。

### 5.5 Ops

Ops 服务器配置保存在主业务库，支持 SSH 连接测试、文件上传和交互式终端。认证方式包括 SSH Agent、密钥路径和密码相关配置。交互式 session 只存在内存中，关闭应用或断开连接后不会持久化。

### 5.6 OCR

PaddleOCR 可通过环境设置页安装，也可以手动安装。若可执行文件不在 PATH 中，可设置 `NANO_AGENT_PADDLEOCR_BIN`。

## 6. 观测与排查

观测系统默认记录部分关键类别，重点覆盖 LLM、MCP、Ops、部分工具和数据库操作。排查路径：

1. 在设置页打开观测面板。
2. 按 trace 查看同一次对话或操作的 span。
3. 检查 status、duration、operation、error 和 metadata。
4. 如需释放空间，可使用清空观测数据功能。

观测管线的原则是非阻塞：写入失败会打印错误，但不会让用户操作失败。

## 7. 安全检查清单

开发涉及工具执行或文件系统时，应确认：

- 是否使用真实 `project_path` 或明确的 `temp/` 根目录，而不是显示名拼路径。
- 是否通过相对路径归一化防止越界。
- 是否对写入、删除、命令执行保留用户确认。
- 是否避免把 API key 写入日志、观测摘要或错误详情。
- 是否避免把大型文件完整注入模型上下文。
- 是否让外部 MCP 工具结果以可见消息形式回到会话。
- 是否保留图片附件的 `.nano-agent/uploads/images/` 目录限制。


